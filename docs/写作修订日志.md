## 从 Claim-Evidence 到页面叙事

本项目后期的核心改写逻辑不是“继续堆结果”，而是按以下顺序组织：

1. 先确认要讲的主判断是什么  
2. 再去 `claim_evidence_table.csv` 找计量证据和代表文献  
3. 再决定这条证据适合放在论文、README 还是 HTML  
4. 最后压缩成一页能在 20-40 秒内讲清的表达

这意味着：

- `claim_evidence_table.csv` 不只是备查表，而是答辩叙事的上游源文件。
- HTML 页面的新增“总论点页”“证据链页”“里程碑页”“技术路线页”，本质上都是对已有 CER 结构的可视化重组。
