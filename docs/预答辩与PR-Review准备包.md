# 预答辩与 PR-Review 准备包

> 更新日期：2026-06-06
> 用途：作为第 24、28-32 次课的准备材料，覆盖预答辩路线、检查单、高频问答与待回填模板。
> Lesson 27-28 补充：第 14 周不是预答辩，正式答辩按随机顺序进行；本文件仅作为答辩准备与待回填记录，不伪造课堂抽签和现场反馈。

---

## 1. 主答辩介质决策

- **主讲材料**：`项目展示.html`
- **主讲策略**：按学术综述答辩逻辑进行全屏翻页讲述
- **备份材料**：现有 `ppt制作/项目展示_无动画.pptx` 保留，但不作为主线推进

理由：

- 当前 HTML 版本已具备更好的信息密度、结构承载力和现场讲述节奏。
- 现有 PPT 视觉与逻辑承载不如 HTML 自然，强行回转为 PPT 会消耗大量时间但不一定提升完成度。

## 2. 正式答辩讲述路线

课件给出的正式答辩规则是“6 分钟汇报 + 1.5 分钟问答 + 0.5 分钟切换”。如果现场采用更短时长，本项目按以下 6 分钟版本压缩；若允许 15 分钟，可展开每个结果页。

### 2.1 6 分钟压缩版

| 段落 | 目标 | 对应页面 |
|---|---|---|
| 0:00-0:40 | 题目、研究背景与 RQ | 封面 + 背景 + RQ |
| 0:40-1:40 | 数据口径、筛选与 Methods 透明度 | 数据来源、检索式、质控、参数 |
| 1:40-3:40 | 3图1表支撑核心发现 | 发文趋势、关键词/共被引、代表文献表 |
| 3:40-4:50 | 证据链、技术迁移路径与前沿判断 | 证据链、里程碑、技术路线 |
| 4:50-5:35 | 贡献与局限 | 结论与未来页 |
| 5:35-6:00 | GitHub 复现路径、AI 使用说明与分工 | 产出矩阵 + 致谢 |

### 2.2 展开版

若课堂允许 15 分钟，可按“背景/RQ → 数据方法 → 发文趋势 → 热点聚类 → 共被引知识基础 → 突现与时间线 → 技术路线 → 贡献局限 → GitHub 与分工”的顺序展开。

## 4. 高频问答清单

### Q1：为什么要同时保留 643 和 147 两个口径？

答题要点：

- `643` 是 WoS 主数据集，适合做国家/机构分布与宏观统计
- `147` 是 DL 纯净子集，适合做 CiteSpace 热点、知识基础与前沿分析
- 两套口径不是冲突，而是针对不同分析层级的分流设计

### Q2：为什么这个领域直到 2022-2024 才明显爆发？

答题要点：

- Transformer 先在 NLP 建立，再经 ViT/Swin 进入 CV
- 半导体制造场景需要更高质量视觉 backbone 和更成熟工程方案
- 因此存在约 1 年方法传导 + 场景吸收的延迟

### Q3：中国发文最多，是否意味着中国最强？

答题要点：

- 发文量说明投入和应用活跃度领先
- 但知识奠基文献仍主要来自通用 AI 领域的非中国团队
- 因此当前更像“应用验证领先”，不完全等于“原创架构领先”

### Q4：为什么 HTML 可以作为答辩材料？

答题要点：

- 它不是普通网页，而是按翻页逻辑构建的单页学术幻灯片
- 结构承载、图文密度和现场讲述节奏优于当前 PPT
- 同时保留在线公开展示与课程交付的双重价值

### Q5：AI 在项目中起了什么作用？

答题要点：

- 主要参与结构整理、代码实现、页面开发和文档收口
- 不负责最终研究判断与事实口径
- 所有数字、文献与核心结论均由人工复核
